# Target authorization

Repository access, public reachability and deployment discovery confer no target-testing authority. A LaunchGate OWNER/ADMIN explicitly authorizes a provider-verified deployment, with a version, principal/role, start/expiry, exact hostname, port, operations, request/concurrency/duration limits and revocation state. Developers can request runs against existing authorization; viewers cannot execute. Current authorizer and requester memberships are checked again during work.

The implemented proof method is PROVIDER_OWNERSHIP_VERIFICATION. The Vercel adapter requires confirmed team OWNER membership, project account ownership, exact deployment ID, repository numeric ID and commit SHA. Operator configuration binds the provider credential to one LaunchGate organization/project. A public or limited deployment response is insufficient. Proofs last one hour; authorization cannot outlive its proof and can be revoked sooner. Removing/revoking the Vercel connection, repository connection, GitHub installation, organization/project, membership or environment stops execution.

Proof verification contacts only Vercel's fixed API, never the proposed target. Consequently there is no unauthenticated challenge-fetch SSRF exception. The Phase 1 authorization contract remains the common interface; a future deployment-challenge adapter must establish a separate, explicitly scoped proof-fetch authorization before making any target request. That adapter is not implemented here.

Environment types are PREVIEW, STAGING and SANDBOX. V1 accepts only provider-generated immutable `*.vercel.app` deployment URLs from deployment metadata, not user-supplied aliases or production targets. Connections and proofs are server facts, not browser writes. Deployment identity and commit are immutable. Composite FKs tie snapshots, deployment commit, authorization version, invariant confirmations, jobs, attempts and evidence to their tenant/project and parent run.

The only executable operation is `resource.read`: one root GET infrastructure probe. There are no attack suites, customer scripts, fixture creation, payment calls or spend-bearing AI calls. Payment policy is TEST_ONLY and provider spend must be zero. Invariants are versioned confirmed policy selections; they do not become executable or proven merely by inclusion in a run.

Transport rejects credentials in URLs, non-HTTPS, non-443, IP literals, localhost/internal names, unauthorized hosts and Unicode/punycode host ambiguity. It resolves all DNS answers, rejects private/link-local/loopback/metadata/multicast/reserved/transition addresses for IPv4/IPv6, then pins the chosen validated address on the actual TLS connection. Certificate verification and original-host SNI remain enabled. Connections do not reuse a previous DNS result and do not honor proxy environment variables. All redirects stop; credentials are never forwarded. Responses are streamed/count-limited without retaining bodies.

Authorization/fencing and durable request budgets are checked after DNS resolution immediately before transport. Limits include request, concurrency, rate, response bytes, attempt deadline, grant lifetime and artifact bytes. Revocation or cancellation aborts the local request on the next heartbeat. Production egress isolation remains a backend responsibility and must independently prevent direct network access by a compromised runner.
